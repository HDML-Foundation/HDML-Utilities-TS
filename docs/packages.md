# Packages — public API per workspace

> **Scope:** Per-package public surface (exports, key types, runtime behaviors). Open this
> when you need to know what a specific `@hdml/*` package offers without reading its source.
> For how packages depend on each other and the end-to-end pipeline, see [architecture.md](architecture.md).
> For wire formats, see [schemas.md](schemas.md).

All packages publish at the **same version** (currently `0.0.2-alpha.26`). All emit CJS +
ESM + `.d.ts` + minified IIFE. Each runtime-bearing `index.ts` also registers itself on
`globalThis["@hdml/<name>"]` as a side-effect — see [architecture.md#globalthis-side-effects](architecture.md#globalthis-side-effects-every-entry-point).

## @hdml/schemas

**Purpose:** TypeScript FlatBuffers bindings — the wire-format contract.
**Source:** Generated by `flatc --ts` from [HDML-Schemas/src/*.fbs](../HDML-Schemas/) at
build time. Output lands in `packages/schemas/src/document/` and `packages/schemas/src/enum/`,
both gitignored.
**Entry point:** [packages/schemas/src/index.ts](../packages/schemas/src/index.ts).

Exports two groups of names — **enums** and **structs** — re-exported from generated files.

Enums: `AggregationTypeEnum`, `ConnectorTypesEnum`, `DataTypeEnum`, `DateUnitEnum`,
`DecimalBitWidthEnum`, `FilterNameEnum`, `FilterOperatorEnum`, `FilterTypeEnum`,
`JoinTypeEnum`, `OrderTypeEnum`, `TableTypeEnum`, `TimeUnitEnum`, `TimeZoneEnum`.

Structs: `HDOMStruct`, `ConnectionStruct`, `ConnectionOptionsStruct`,
`ConnectionParametersStruct`, per-connector parameter structs (`BigQueryParametersStruct`,
`JDBCParametersStruct`, `GoogleSheetsParametersStruct`, `ElasticsearchParametersStruct`,
`MongoDBParametersStruct`, `SnowflakeParametersStruct`), `ModelStruct`, `TableStruct`,
`JoinStruct`, `FrameStruct`, `FieldStruct`, `FieldTypeStruct`, type-options structs
(`CommonParametersStruct`, `DateParametersStruct`, `DecimalParametersStruct`,
`TimeParametersStruct`, `TimestampParametersStruct`, `DataTypeOptionsStruct`,
`UnspecifiedParametersStruct`, `ExpressionParametersStruct`), filter structs
(`FilterStruct`, `FilterClauseStruct`, `FilterOptionsStruct`, `NamedParametersStruct`,
`KeysParametersStruct`), and the document-files trio: `FileStruct`, `DocumentFilesStruct`,
`DocumentFileStatusesStruct`.

**Build hook:** `npm run compile_fbs` regenerates from `.fbs`. The `build` script runs it
automatically before lint.

**Dep:** `flatbuffers` (24.3.25 — must match the `flatc` version).

## @hdml/types

**Purpose:** Hand-authored TypeScript interfaces and lookup tables that mirror the FlatBuffers
schema, plus the HDML tag / attribute / enum-value name constants used by the parser and
stringifier.

**Entry point:** [packages/types/src/index.ts](../packages/types/src/index.ts).

**Object interfaces:** `HDOM`, `Connection`, `Model`, `Table`, `Join`, `Frame`,
`Field`, `FieldType`, `FilterClause`, `Filter`, and per-connector / per-parameter parameter
types (`BigQueryParameters`, `JDBCParameters`, `GoogleSheetsParameters`,
`ElasticsearchParameters`, `MongoDBParameters`, `SnowflakeParameters`, `ConnectionOptions`,
`CommonParameters`, `DateParameters`, `DecimalParameters`, `TimeParameters`,
`TimestampParameters`, `ExpressionParameters`, `NamedParameters`, `KeysParameters`).

★ **`Field.key: null | string`** — the named key group a field belongs to
(`"pk"`, an alternate unique key, …), authored as `hdml-field@key` and added
at 019 step 11 together with `FieldStruct.key` in `HDML-Schemas`. It is a
**string, not a boolean**, because a key is a *set*: a boolean cannot tell one
column of a composite primary key from an alternate unique key on its own, and
the vocabulary deliberately does not enumerate key names. `key` is legal only
on a field directly inside an `hdml-dataset`; in the other four positions the
parser reports `misplaced-key`.
★ **It reaches Go as of 019 step 22.** HDIO-Server's nested `HDML-Schemas` pin
was deliberately held one commit behind from step 11 until then; it is now at
`4c338b5` like the other two, and the Go binding carries a `Key()` accessor at
vtable offset 18. ⚠ **The file is `internal/schema/document/FieldStruct.go`**,
PascalCase — `flatc --go` names Go output that way, and there is no
`field-struct.go` (an earlier version of this note said there was).
It is still regenerated by hand, with `make flatc-go`, guarded by the
`flatc-go-check` prerequisite on `make build` / `make test`. **Nothing in Go
reads `key`** — the field is written here, carried through FlatBuffers, and
unread on the Go side; the fan-out detector it exists for is a later project.

**Lookup tables** (string constants — used by parser to read attributes and by stringifier to
emit them):

- `HDML_TAG_NAMES` — **every tag of the HDML language, 34 members in two
  groups.** The twelve **data** tags (HDQL): `hdml-connection`, `hdml-frame`,
  `hdml-model`, `hdml-dataset`, `hdml-join`, `hdml-connective`,
  `hdml-filter-by`, `hdml-filter`, `hdml-group-by`, `hdml-split-by`,
  `hdml-sort-by`, `hdml-field`. Then the twenty-two **display** tags (HDVL):
  `hdml-view`, `hdml-cartesian-plane`, `hdml-polar-plane`,
  `hdml-continuous-scale`, `hdml-datetime-scale`, `hdml-ordinal-scale`,
  `hdml-line`, `hdml-area`, `hdml-bar`, `hdml-point`, `hdml-arc`, `hdml-rule`,
  `hdml-text`, `hdml-pie`, `hdml-cluster`, `hdml-stack`, `hdml-axis`,
  `hdml-tick`, `hdml-label`, `hdml-grid`, `hdml-legend`, `hdml-fallback`. One
  flat enum for the whole language — there is no parallel display-only tag
  enum. The display half is consumed by HDML-Components, not by the parser or
  stringifier.
  - ★ **`hdml-dataset`, not `hdml-table`** — renamed at 019 step 07, along
    with `DATASET_ATTRS_LIST` and `DATASET_TYPE_VALUES`. The `Table`
    interface, `TableStruct`, `TableTypeEnum` and the `getTableData` handler
    deliberately did **not** move (that is a `.fbs` change), so *tag*
    `hdml-dataset` ↔ *type* `Table` is expected.
  - ★ **`hdml-text` is the 25th member and the 13th display tag**, added at
    019 step 14 (item 5) and **inserted after `hdml-rule`, before
    `hdml-pie`** — not appended after `hdml-fallback` (S15). It goes with the
    marks because the display block is a line-for-line transcription of
    SPEC §2's inventory order and `hdml-text` is the seventh *mark*, while
    `hdml-pie` is its own layout layer. The totals a gate reads — **34** and
    **22** — are the same under either placement. ⚠ **Nothing implements it
    yet** — the element is step 41's, in `@hdml/components` — so the tag and
    its `TEXT_ATTRS_LIST` ship as vocabulary with no reader for one publish.
- `*_ATTRS_LIST` — one per element that has its own attributes; elements with
  none (`hdml-filter-by`, `hdml-group-by`, `hdml-sort-by`, `hdml-fallback`)
  have no enum. **29 are exported**, carrying **217** members between them
  (56 data + 161 display).
  **Data (8):** `CONN_ATTRS_LIST`, `MODEL_ATTRS_LIST`, `DATASET_ATTRS_LIST`,
  `JOIN_ATTRS_LIST`, `FRAME_ATTRS_LIST`, `FIELD_ATTRS_LIST`,
  `FILTER_ATTRS_LIST`, `CONNECTIVE_ATTRS_LIST`.
  **Display (21):** `VIEW_`, `CARTESIAN_PLANE_`, `POLAR_PLANE_`,
  `CONTINUOUS_SCALE_`, `DATETIME_SCALE_`, `ORDINAL_SCALE_`, `LINE_`, `AREA_`,
  `BAR_`, `POINT_`, `ARC_`, `RULE_`, `TEXT_`, `PIE_`, `CLUSTER_`, `STACK_`,
  `AXIS_`, `TICK_`, `LABEL_`, `GRID_`, `LEGEND_ATTRS_LIST`. The display enums
  carry binding, domain and configuration keys only — HTML global attributes
  (`class`, `style`, `aria-*`) are deliberately out, with `hidden` the one
  exception (it is load-bearing vocabulary on `hdml-bar`, `hdml-area` and
  `hdml-stack`, where it re-derives a layout container's relation).
  - ⚠ **The 21 display figure and the 29 package figure are both right, about
    different surfaces.** `HDML_TAG_NAMES.test.ts`'s `ATTRS_LISTS` record is
    display-only; a reader counting `*_ATTRS_LIST` off the package sees all
    29. A gate that conflates them fails on correct code (019 step 15).
  - ★ **`count` and `format` are gone** (019 step 16, items 18 + 19). `count`
    left `TICK_`, `GRID_`, `LABEL_` and `LEGEND_ATTRS_LIST`; `format` left
    `LABEL_` and `LEGEND_`. Those four now hold **three members each**
    (`channel`, `step`, `values`) — **18 → 12**. Both are now registered CSS
    properties, `--hdml-tick-count` and `--hdml-text-format`, authored in a
    stylesheet rather than on the element, because how many ticks a guide
    draws and how a label formats its value are appearance, not data.
    **This is breaking**, which is why the pass published `0.0.2-alpha.26`
    rather than a patch (019 step 18, 2026-10-05). ⚠ **`AGGREGATION_VALUES.COUNT`
    is a different thing** — the `count` *value* of `hdml-field@aggregation`
    — and survives.
  - ★ **Ten of the display enums carry 50 `initial-{slot}` members** (019
    step 15, item 1): the ten mark enums (`POINT_`, `BAR_`, `LINE_`, `AREA_`,
    `ARC_`, `RULE_`, `STACK_`, `CLUSTER_`, `PIE_`, `TEXT_`) declare an
    `initial-{slot}` for **every** slot they publish, spelled `initial-` plus
    the exact slot attribute name with no transformation, so a generator can
    derive the whole set from a channel name without a mapping table. The ten
    hold **116** members, 50 of them `initial-*`. The four non-slot
    attributes get none — `source` is the frame binding, and `hidden`,
    `closed` and `offset` are flags with no datum — and **no** scale, plane,
    guide, view or legend enum gets any. ⚠ **Nothing reads them yet**: the
    consumer is step 43's, in `@hdml/components`.
- `*_VALUES` — `AGGREGATION_VALUES`, `BITWIDTH_VALUES`, `CONN_TYPE_VALUES`,
  `CONNECTIVE_OP_VALUES`, `DATASET_TYPE_VALUES`, `DT_UNIT_VALUES`,
  `FIELD_TYPE_VALUES`, `FILTER_NAME_VALUES`, `FILTER_TYPE_VALUES`,
  `JOIN_TYPE_VALUES`, `ORDER_VALUES`, `TIMEZONE_VALUES`. Twelve enums.
  `AGGREGATION_VALUES`' seven members include `count`, `countDistinct` and
  `countDistinctApprox` — unrelated to the `count` **attribute** removed from
  the four guide enums above.
- `HDQL_DIAGNOSTIC_CODES` — the 11 reasons `parseHDML` drops an element, each
  reported as an out-parameter diagnostic rather than thrown. The 11th,
  `misplaced-key`, arrived with `hdml-field@key` at 019 step 11.

**No runtime side-effects.** Pure types + constants. `test` script is intentionally empty.

**Deps:** `@hdml/schemas` (for the enum types), `flatbuffers`.

## @hdml/parser

**Purpose:** Parse HDML/HTML strings into TS objects.

**Entry point:** [packages/parser/src/index.ts](../packages/parser/src/index.ts).

**Exports:**

| Symbol | Signature | Notes |
|---|---|---|
| `parseHDML(content: string): HDOM` | [packages/parser/src/parseHDML.ts:35](../packages/parser/src/parseHDML.ts#L35) | parse5 + custom tree adapter. Errors log via `console.error` (do not throw). Frames sorted via `sortFrames` before return. |
| `parseHTML(content: string): HTMLElement` | [packages/parser/src/parseHTML.ts:25](../packages/parser/src/parseHTML.ts#L25) | Thin wrapper over `node-html-parser`. `lowerCaseTagName: false`. |
| `sortFrames(frames: readonly Frame[]): Frame[]` | [packages/parser/src/sortFrames.ts:101](../packages/parser/src/sortFrames.ts#L101) | Dependency-safe order: model-rooted `/path` first, then frame-rooted `/path`, then `?model`, then `?frame` (topologically). |
| `HTMLElement` | re-export from `node-html-parser` | — |

**Tree adapter:** [packages/parser/src/hdmlTreeAdapter/hdmlTreeAdapter.ts](../packages/parser/src/hdmlTreeAdapter/hdmlTreeAdapter.ts).
One `get*Data` handler per HDML tag (Connection / Model / Table / Frame / Join /
Connective / Filter / Field). Wrappers `hdml-filter-by`, `hdml-group-by`, `hdml-split-by`,
`hdml-sort-by` have no data of their own — they organize children.

**Identifier-quote normalization.** SQL-bearing attributes are authored with **backticks**
so a `"`-quoted identifier sits inside a double-quoted HTML attribute without `&quot;`; the
tree adapter decodes those backticks to standard double quotes via
[`backticksToQuotes`](../packages/parser/src/hdmlTreeAdapter/backticksToQuotes.ts) when it
reads `hdml-dataset@identifier`, `hdml-field@clause`, and `hdml-filter@clause`/`@field`/`@values`
(`getTableData`/`getFieldData`/`getFilterData` — the *tag* was renamed at 019 step 07, the
*handler* was not). So the **canonical FlatBuffers form uses
double quotes** — `getModelSQL`/`getFrameSQL` emit it verbatim into Trino-valid SQL — and this
is the exact inverse of the `"`→backtick swap the stringifier applies when reconstructing HTML
([`getModelHTML`](../packages/stringifier/src/model.ts#L190),
[`getFieldHTML`](../packages/stringifier/src/field.ts#L332), `getFilterHTML`), closing the
HTML↔struct round-trip. Author style doesn't fork identity: a backtick-quoted and an
equivalently double-quoted document serialize identically.

**Deps:** `parse5`, `node-html-parser`, `@hdml/types`, `@hdml/schemas`.

Dispatches on `ConnectorTypesEnum`. The catalog **name is double-quoted** in `drop`/`create` (identifier), so non-identifier-safe names — e.g. a hyphenated `{tenant}_{conn}` like `tenant-a_maang` — are valid Trino identifiers; the `show catalogs like` name stays a single-quoted string literal. | [packages/stringifier/src/connection.ts:25](../packages/stringifier/src/connection.ts#L25) |

| `getModelHTML(model: ModelStruct, level?: number): string` | HDML `<hdml-model>` element. | same file |
| `getFrameSQL(frame: FrameStruct, from: {name, sql}, level?: number): string` | `with "<src>" as (…) select … from "<src>" [where] [group by] [order by] offset N limit N`. Caller threads upstream SQL via `from`. | [packages/stringifier/src/frame.ts:17](../packages/stringifier/src/frame.ts#L17) |

Indentation comes from a single 2-space constant `t` in [packages/stringifier/src/constants.ts](../packages/stringifier/src/constants.ts).

**Multi-table model field aliasing.** When a `ModelStruct` carries multiple tables (joined
or not), `getModelSQL` emits the outer `SELECT` with every field aliased as
**`"{table-name}_{field-name}"`** — see
[packages/stringifier/src/model.ts:51-63](../packages/stringifier/src/model.ts#L51-L63).
Downstream consumers (a `getFrameSQL` call sourcing this model, or an HDML author writing
an `hdml-frame` with `source="?hdml-model=…"`) must reference parent fields by that
compound name — bare field names won't resolve when several tables carry the same column. The rule
applies even to single-table models. Frame-to-frame projection in `getFrameSQL` performs
no such rewriting: parent-frame fields are exposed by their declared `name`.

**Deps:** `@hdml/schemas`, `@hdml/types` (dev: `@hdml/buffer` for tests).

## @hdml/buffer-adjacent: @hdml/hooks

**Purpose:** WASI/Javy I/O helpers — read/write JSON, strings, and `Uint8Array`s over
stdin/stdout/stderr inside `hdio.wasm`.

**Entry point:** [packages/hooks/src/index.ts](../packages/hooks/src/index.ts).

| Symbol | Reads from / writes to | Notes |
|---|---|---|
| `readUint8Array(): Uint8Array` | stdin (fd 0) | 1 KiB chunks until `readSync` returns 0. [packages/hooks/src/io/readUint8Array.ts](../packages/hooks/src/io/readUint8Array.ts) |
| `readString(): string` | stdin | TextDecoder over `readUint8Array`. |
| `readJson<T = unknown>(): T` | stdin | `JSON.parse(readString())`. |
| `writeUint8Array(bytes)` | stdout (fd 1) | — |
| `writeString(s)` | stdout | TextEncoder. |
| `writeJson(v)` | stdout | `JSON.stringify`. |

**Host contract:** The Go host (HDIO-Server) wires temp files on a tmpfs to fd 0/1, plus
fd 2 for stderr logs. See [integration.md#wasm-host-abi](integration.md#wasm-host-abi).

**The two bin entries.** Beyond the I/O helpers, `@hdml/hooks` ships the bodies of both
predefined WASM modules: [`src/parser.ts`](../packages/hooks/src/parser.ts) →
`bin/parser.min.js` → `hdml_parser.wasm`, and
[`src/compiler.ts`](../packages/hooks/src/compiler.ts) → `bin/compiler.min.js` →
`hdml_compiler.wasm`. Both are **top-level IIFEs**: each reads its input, computes, and
writes its envelope at module scope, so importing one *runs* it. Both resolve `@hdml/*`
off `globalThis` rather than through a TS import, so a broken `hdio-javy-core` link throws
at `_start` instead of silently importing nothing. ⚠ `compile_bin` bundles `esm/`, **not**
`src/` — a hand-run `compile_bin` against a stale `esm/` ships the previous entry and looks
like a runtime defect, so build the workspace rather than the one script.

**The `plugin` version echo (019 step 16, A4).** Both entries now set
**`plugin: globalThis["@hdml/version"]`** on the envelope they write — on **every** return
shape, success and error alike, because it is spread on at the entry rather than inside
`buildManifest`'s four return sites or the five `compile*` branches. A predefined module's
import surface carries **no version and no hash**: it imports exactly
`hdio-javy-core::{cabi_realloc, invoke, memory}`, and the plugin's only identity marker is
a custom wasm section holding the bare string `hdio-javy-core`. So a module built against
one plugin and run against another binds to the *running* plugin's globals, with no
instantiate error and byte-identical output — measured. HDIO-Server embeds its
`.fetched-version` marker and compares.
⚠ The **field** is `plugin`; the **global** is `@hdml/version` — the names differ on
purpose, because Go reads `json:"plugin,omitempty"`. An absent global leaves the field
`undefined`, which `JSON.stringify` drops, and that is what an older plugin produces.
⚠ **Nothing compares it yet** — the Go side is 019 **step 24's** — so for one publish the
field is written and unread.

**Compiler branch (`compiler.min.js`):** beyond the I/O helpers, `@hdml/hooks` ships the
`hdml_compiler.wasm` body — the `connection` / `source` / `sql` / `effective` output modes
([compileConnections.ts](../packages/hooks/src/compileConnections.ts),
[compileSource.ts](../packages/hooks/src/compileSource.ts),
[compileSql.ts](../packages/hooks/src/compileSql.ts),
[compileEffective.ts](../packages/hooks/src/compileEffective.ts)) plus the shared
[applyAdaptation.ts](../packages/hooks/src/applyAdaptation.ts).

| Symbol | Notes |
|---|---|
| `applyAdaptation(dom, policy, role): void` | Mutates the reconstructed-document DOM **in place** for the caller's single active `role` (single-role contract, Slice D D1). Selects only `policy.roles[role]` and applies its rules in **array order** — a later `set-attribute` on the same `(node, attribute)` overwrites an earlier one, so broad-then-specific resolves to the specific value (D5). `remove-element` deletes the matched element and its whole subtree; `set-attribute` writes `String(rule.value)` (Go `interface{}` → string coercion) to **any** attribute, structural ones (`source` / `identifier` / `name`) included — no allowlist (D6). A `${scope.*}` / `${env.*}` in a forced value is left literal here; in `sql` it runs **before** injection, which then resolves it. |
| `AdaptationError` (extends `Error`) | Fail-loud carrier (D3): thrown on a selector the DOM rejects or an unknown `action`. The `sql` / `effective` branches' round-trip `try/catch` map it to `adaptation_failed`. |
| `compileEffective(deps, input)` | The `effective` mode (Slice D, D2): reconstruct the document (shared `reconstructDocument`) → `parseHTML` → `applyAdaptation` for `input.role` → return `{ result: [dom.toString()] }`, length 1. **Stops** at the adapted DOM — no `parseHDML`, no `${…}` injection, no `getFrameSQL`, so templates stay literal. Lenient (no `missing_model` gate); with no policy / role it is byte-identical to `source` (D5). Errors: `structurize_failed` (reconstruct) \| `adaptation_failed` (parse / adapt / serialize). |

No-op identity (D5): an absent `policy`, a `role` not in `policy.roles`, or a selector
matching nothing leaves the DOM unchanged. The body is **single-sourced** — `applyAdaptation`
and `reconstructDocument` are imported by both `compileSql.ts` and `compileEffective.ts`.

**Dep:** `@hdml/parser`, `@hdml/types`, `@hdml/schemas`, `@hdml/buffer`,
`@hdml/stringifier`, `@hdml/hash`. (The parser provides the `parseHTML` DOM the adaptation
selectors run over; the I/O primitives themselves do not touch HDML.)

## @hdml/common

**Purpose:** Shared third-party re-exports — the same `apache-arrow`, `uuid`, and
`throttle-debounce` instances every other package and every host consume. Avoids duplicate
copies in the Javy bundle.

**Entry point:** [packages/common/src/index.ts](../packages/common/src/index.ts).

Exports `arrow`, `uuid`, `throdeb` namespaces; also writes them to
`globalThis["@hdml/common"]`.

**Deps:** `apache-arrow ^11.0.0`, `uuid ^10.0.0`, `throttle-debounce ^5.0.2`.

Not typically imported by end users — most packages pull only what they need from
`@hdml/common`. Apache Arrow is here because HDIO's query path returns Arrow streams to the
client; staging it in `@hdml/common` keeps the version pinned across hosts.
